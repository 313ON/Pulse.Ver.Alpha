# سفرهای اصلی کاربر

الگوی عمومی هر سفر: Trigger → Intent → Guided steps → Decisions → Assistance → Validation → Success → Recovery.

## سفرهای برنامه‌ریزی و اجرا

| سفر | مسیر هدف و کمک سیستم | موفقیت | بازیابی |
|---|---|---|---|
| ورود اول | ورود → تشخیص نقش/واحد/چرخه → نمایش «قدم بعدی» | dashboard شخصی و context معتبر | حساب/داده ناقص با توضیح و ارجاع به مدیر |
| onboarding | سازمان → نقش → واحد → مسئولیت → چرخه → ترجیحات | نخستین کار مفید آماده | امکان رد مرحله غیرضروری و تکمیل بعدی |
| ایجاد هدف | نیت ایجاد هدف → انتخاب برنامه/واحد → عنوان/نتیجه → مرور → ذخیره | هدف پیش‌نویس با روابط معتبر | حفظ draft و نمایش فیلد ناقص |
| ایجاد هدف جزئی | بازکردن هدف → «افزودن مسیر تحقق» → عنوان/مالک → مرور | objective زیر هدف درست | پیشنهاد parent معتبر؛ عدم نمایش ID |
| ایجاد فعالیت | objective → نتیجه مورد انتظار → مالک/تخصیص → مرور | activity با assignments معتبر | بازگشت به مرحله قبلی بدون از دست‌رفتن ورودی |
| ایجاد اقدام | activity → عنوان/خروجی/مسئول/مهلت → وضعیت → مرور | action از application service ساخته شود | خطای رابطه با توضیح «این فعالیت متعلق به هدف انتخابی نیست» |
| پیشرفت اقدام | کارهای من → ثبت درصد/وضعیت/مانع → تأیید سبک | progress و audit ثبت شود | stale data با refresh و مقایسه |
| بازبینی KPI | شاخص → دوره/مقدار/شاهد → تفسیر → ثبت | measurement قابل ردیابی | واحد/جهت/مقدار نامعتبر با راهنمای مثال |
| عملکرد واحد | انتخاب واحد/چرخه → خلاصه → drill-down | KPI، تأخیر و ریسک قابل فهم | داده ناقص به‌صورت صریح «نیازمند تکمیل» |
| گزارش | انتخاب نوع/بازه/واحد → preview → export | artifact سالم و پیام موفقیت | خطای export با retry و حفظ فیلترها |

## سفرهای پشتیبانی و مدیریت

| سفر | مسیر | موفقیت/بازیابی |
|---|---|---|
| import | انتخاب فایل → پیش‌نمایش → نگاشت → بررسی provenance/governance → تأیید مجاز → materialize | وضعیت APPROVED/REVIEW_REQUIRED شفاف؛ blocked هرگز canonical نمی‌شود |
| خطا | پیام چه شد/چرا/چه کنم → اصلاح یا retry → diagnostics پیشرفته | کاربر بدون متن stack trace قدم بعدی دارد |
| جستجو | query انسانی → پیشنهاد و فیلتر → نتیجه permission-aware → context | نتیجه با نوع/وضعیت/واحد و مسیر بازگشت |
| اعلان | مشاهده اعلان → گروه‌بندی نیازمند اقدام/اطلاع → بازکردن context → علامت‌گذاری | هیچ اعلان بدون action یا دلیل باقی نماند |
| تنظیم مدیر | کاربران/نقش/واحد/import/تنظیم → preview تغییر → تأیید → audit | تغییر مجاز، قابل ردیابی و قابل بازگشت تا حد امکان |

## اصل فرم

فرم‌های بزرگ به stepper/wizard شکسته می‌شوند. سیستم parent، شناسه، وضعیت پیش‌فرض و مقادیر امن را خودش resolve می‌کند و قبل از persistence اعتبارسنجی دامنه اجرا می‌شود.
